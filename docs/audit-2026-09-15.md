## Validation and repository practices

- 44 tests pass on Windows and Linux for Python 3.12, 3.13, and 3.14; the full six-case/two-variant comparison is exercised in the suite.
- Ruff lint and formatting, annotated application/script functions checked by mypy, and an 85% minimum combined statement/branch coverage gate are required.
- The runtime has no third-party dependencies. All 36 locked development packages had no known vulnerability reported by pip-audit on this date; CI repeats the audit against current advisories.
- Pinned GitHub Actions, read-only workflow tokens, explicit required checks, local hooks, staged-content guards, CODEOWNERS, PR/issue templates, and Dependabot updates are configured.
- Feature work goes through `feat/*` → `dev` → `main`. Both integration branches require PRs, current successful checks, and resolved conversations; force pushes/deletion are blocked. The solo-maintainer configuration requires no external approval.

Initial full CI proof: [successful run at `8e744ae`](https://github.com/andersj05/SellsideDistillation/actions/runs/34984733157). Later PR/branch checks are available in the repository's Actions and merged-PR history.

## Remaining limits

Real-report parsing, expert evaluation, live agents, and empirical research-method transfer remain pending. The adapter boundary is implemented in the application; arbitrary Python is not OS-isolated. Freeze manifests are unsigned. Budgets check elapsed time cooperatively, intake is limited to 64 MiB, and there is no whole-process memory/disk quota. Persistent storage failure can prevent recovery records from being written. Browser visual QA remains pending after the local-file URL was rejected by browser policy.

No new security finding exclusions or accepted risks were adopted by this audit. A new deployment or materially different execution route requires a fresh review.
